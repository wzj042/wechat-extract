# 私有仓库共享检查（2026-11-04）

当前目标是私有仓库托管和有限共享，不准备公开发行或选择全库开源许可证。保留来源归属与已知许可问题，但本次检查聚焦于是否混入不应提交的内容。

## 本次发现与处理

人工检查在 `tests/test_chatroom.py` 发现一个具体昵称，不能确认它是合成占位符，已替换成“测试名片甲”。旧 Git 提交仍含原值：普通修复提交不会清除历史。本地开发历史保留，交付给私有远程时使用经过检查的、无旧历史的源码快照仓库；不要把开发目录的全部 refs 推过去。

Git 作者/提交者身份以及来源仓库的作者署名仍保留。前者是提交元数据，后者是来源归属；这两类信息会对私有仓库的获授权读者可见，不等同于聊天数据。没有为消除署名而改写来源说明。

本次还逐项核对了测试中的密钥、微信 ID、消息 XML、公众号链接和表情 CDN URL：密钥是显式合成值或运行时生成，ID 为测试账号，URL 查询参数为占位数据。真实媒体测试只从环境变量获取路径与密钥，默认跳过，代码中不带实际值。文档中的真实媒体验证仅保留数量与结果，没有消息正文或真实账号标识。

## 不随仓库提交

数据库、解密缓存、密钥、账号配置、运行日志、媒体附件、虚拟环境、构建缓存、本地审计用的敏感词表，以及原工作区的生产/智能体配置。只检查新项目跟踪文件，不把其他项目或记忆库打包。依赖锁里的下载地址与校验哈希、上游 commit 和许可证文本是必要项目资料，保留。

当前 `.gitignore` 主要防止常见输出进入跟踪；它不能保护已经跟踪的文件，也不能保证任意命名的私有文本不被提交。

## 重跑检查

```powershell
uv run python tools/check_release.py --privacy-only --json
uv run python tools/check_release.py --privacy-only --denylist output/private-denylist.txt --json
```

敏感词表为本地 UTF-8 文本，每行一个需要排除的精确字符串，放在被忽略的 `output/` 中。检查覆盖当前跟踪文件、暂存区和所有本地 refs 可达的历史；输出只给文件和规则，不复述命中的敏感值。开发库的历史保留了本次替换前的昵称，所以使用本次敏感词表检查开发库应失败；对无旧历史的交付副本应通过。

不带 `--privacy-only` 的命令仍执行未来公开发布的许可检查。其许可失败不应被误报为本次私有源码内容扫描发现了密钥，也不意味着隐私扫描通过就解决了所有权属问题。

构建包另行检查文件清单和文本内容，排除 `.git` 与运行数据。自动检查只是有限模式匹配；新增真实样本、日志、截图或其他二进制前仍需人工复核。
