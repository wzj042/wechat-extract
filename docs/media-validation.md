# 媒体补齐验证（2026-10-20）

本轮顺序：少量真实样本验证 → 按消息导出图片 → 资源索引及语音、视频、文件定位与导出。

本文记录 2026-10-20 当时的验证范围，不代表当前功能清单；当前能力以 [README](../README.md) 和 [MCP 服务](mcp.md) 为准。

## 有限真实样本验证

从现有明文缓存选取 2 个会话、2 个消息分片中的 11 条真实消息，构造工作区内的行子集；它不是完整数据库快照。没有重新提取进程密钥或全量解密。私有样本、附件输出及定位上下文不随仓库发布，本文仅记录数量与结果。

- 11 条消息按会话、分片和 local_id 回读身份全部一致。
- 3 条图片中，资源索引补充后确认 2 条已缓存、1 条未缓存。此前直接按 XML MD5 查找会把这 2 条也误报缺失，因为实际资源 file-id 不同。
- 2 条已缓存图片均实际解密并通过 Pillow 完整校验。其中一条使用 `ciphertext` 模式成功；另一条原图及中图需要显式 `plaintext` 模式。没有自动改用缩略图。
- 2 条语音已导出原始 SILK，仅检查头部，未验证音频解码。
- 其余 3 条文本、3 条应用消息不属于当前自动媒体分派支持的类型，返回 `unsupported`。
- 本轮没有真实视频或普通文件成功导出的证据；这两条链路通过合成数据验证，仍需后续真实样本确认。

旧明文缓存保留 WAL 模式头，在外部只读目录直接打开可能要求创建辅助文件。本轮仅对无 WAL/SHM 且读取前后状态不变的缓存做有限检查，并在可写工作区建立子集；生产读取器没有全局启用会忽略活动 WAL 的 `immutable=1`。

## 防误关联与完整性

合成回归覆盖跨分片重复编号、资源库会话/服务端编号/时间/类型不匹配、独立媒体分片 Name2Id、同名文件误关联、多候选歧义、图片截断、错误密钥、读取期间变化、原子输出及 CLI 非零失败码。

媒体未缓存时不会控制微信下载。图片两种 DAT 长度语义保留显式选择；语音未转 MP3，视频及普通文件仅稳定复制。会话列表、统一诊断命令、完整聊天导出和消息事件监听仍未实现；现有 `watch` 负责数据库刷新。
